> Inverting control to manage object lifecycles.

## Purpose
Details how the Spring IoC (Inversion of Control) container manages object creation and dependency wiring across the InsuranceFlow backend.

---

## Overview
- Primarily uses Constructor Injection via Lombok's `@RequiredArgsConstructor`.
- Eliminates tight coupling between classes.
- Explains the use of `@Qualifier` for resolving ambiguities.

---

## Business Context
A `QuoteService` needs to talk to the `QuoteRepository`, the `ProductRepository`, and the `PremiumCalculatorFactory`. If the service creates these itself (`new QuoteRepository()`), it becomes impossible to test and tightly bound to specific implementations. DI solves this.

> **Analogy**: Like an assembly line worker. The worker (Service) doesn't build their own tools (Dependencies). The factory manager (Spring IoC) hands the worker the exact tools they need when their shift starts.

---

## Backend Implementation

### Constructor Injection vs Field Injection
- **Field Injection (`@Autowired` on a field)**: Avoided. It makes it impossible to instantiate the class in a unit test without a Spring context, and allows circular dependencies to go unnoticed.
- **Constructor Injection**: The project standard. Forces dependencies to be provided at instantiation. We use `final` fields + Lombok `@RequiredArgsConstructor` to generate the constructor automatically.

### Code Example Concept
```java
@Service
@RequiredArgsConstructor
public class QuoteServiceImpl implements QuoteService {
    // Spring automatically injects these via the constructor generated by Lombok
    private final QuoteRepository quoteRepository;
    private final PremiumCalculatorFactory factory;
}
```

## Design Decisions
- **Why DI? Why Spring IoC container?**  
  DI allows us to adhere to the Dependency Inversion Principle (SOLID). We depend on interfaces, and Spring wires the correct implementation at runtime.
- **Why `@Qualifier` or bean names matter?**  
  In the Factory pattern, we inject a `Map<String, PremiumCalculator>`. Spring uses the bean names as the keys in this map, making the bean name a critical part of the business logic.

## Interview Notes
1. **Why is Constructor Injection preferred over Field Injection?**  
   It allows dependencies to be marked `final` (immutable), ensures the object is never instantiated in a partially constructed state, and makes writing plain JUnit tests much easier without needing Mockito extensions.
2. **What happens if there is a circular dependency with Constructor Injection?**  
   The application will fail to start. This is a *good* thing, as it forces you to redesign your architecture to remove the circular logic.
3. **What is Inversion of Control?**  
   Instead of the application code controlling the flow and creation of objects, the framework (Spring) takes control and calls your code/injects objects when needed.
