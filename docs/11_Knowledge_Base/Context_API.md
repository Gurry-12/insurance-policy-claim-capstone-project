# Context API

## What It Is
React Context provides a way to share values across the component tree
without prop drilling. A provider owns the state; consumers read it with
`useContext`. This project uses two top-level providers, `AuthProvider`
and `ThemeProvider`, composed in `src/main.jsx` and consumed through the
custom hooks `useAuth` and `useTheme`.

## Why It Is Used
- Global concerns (authentication session, theme) are needed by every
  page and layout; context avoids threading props through the router.
- Centralizes the session lifecycle (login, logout, silent restore) and
  theme toggling in one place, keeping pages thin.
- The access token itself is kept out of component state and lives only
  in memory via `src/api/tokenStore.js`.

## Where It Is Used in This Project
Verified against `insurance-policy-claim-management-app-ui/src/`:
- `src/context/AuthContext.jsx` exposes `{ token, user,
  isAuthenticated, isRestoring, login, logout }`. On boot it silently
  restores the session via `POST /api/auth/refresh` using the HttpOnly
  refresh cookie, gates the UI behind `isRestoring`, listens for the
  `auth:token-refreshed` window event, and persists only non-sensitive
  markers (`ss_user`, `ss_has_session`) — the access token never touches
  browser storage.
- `src/context/ThemeContext.jsx` exposes `{ theme, toggleTheme }`,
  persists the choice under `ss_theme`, and syncs `data-theme` and
  `data-bs-theme` on `document.documentElement` (drives the role theming
  defined in `src/index.css`).
- Providers composed in `src/main.jsx`: `ThemeProvider > AuthProvider > BrowserRouter > App`.
- Consumers: `src/hooks/useAuth.js` and `useTheme.js` (throw if used
  outside their provider); route guards in `src/App.jsx`
  (`ProtectedRoute`, `GuestRoute`, `RoleProtectedRoute`,
  `DashboardRedirect`); PDF hooks such as `usePolicyPdf.js` read
  `useAuth().user` for the "generated by" line.

## Common Interview Questions
1. When should you use Context vs props?
   Context for values consumed by many unrelated components (auth, theme);
   props for local, single-owner data.
2. Why keep the access token out of localStorage?
   To reduce XSS exposure; the token lives in memory and sessions are
   silently restored from the HttpOnly refresh cookie.
3. What does `isRestoring` control?
   It keeps the UI in a loading state while the silent refresh runs, so
   guards do not bounce a valid session to the login page.
4. How does AuthContext stay in sync with axios refresh?
   It listens for the `auth:token-refreshed` window event dispatched by
   `src/api/axiosInstance.js` and stores the fresh token.
5. What happens when `useAuth` is used outside `AuthProvider`?
   The hook throws an error, surfacing the misconfiguration early.
6. How is the theme applied at the DOM level?
   `ThemeContext` sets `data-theme` and `data-bs-theme` on
   `document.documentElement`, which CSS variables in `src/index.css`
   read to swap light/dark and role colors.
