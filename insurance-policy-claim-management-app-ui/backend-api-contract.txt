Advanced API Contract Specification
This document provides the full, advanced schema definitions and API contracts for the Insurance Policy Claim Management System backend. It is designed to act as a comprehensive integration guide for the frontend team.

1. System Envelopes & Base Responses
All endpoints (except raw binary/file downloads) return a standard JSON envelope. This ensures frontend clients can write a single, global Axios/Fetch interceptor to handle responses, success notifications, and error toasts.

1.1 Success Envelope (ApiResponseDTO<T>)
Used for all 2xx responses.

json

{
  "message": "string",       // User-facing success message
  "success": true,           // Always true
  "timeStamp": "2023-10-27T10:00:00",
  "data": { ... }            // <T> The typed response object or array
}
1.2 Paginated Envelope (ApiResponseDTO<PageResponseDTO<T>>)
Used for all paginated lists (/page endpoints).

json

{
  "message": "string",
  "success": true,
  "timeStamp": "2023-10-27T10:00:00",
  "data": {
    "content": [ { ... } ],  // Array of <T> objects
    "pageNumber": 0,         // Current page (0-indexed)
    "pageSize": 10,          // Items per page
    "totalRecords": 50,      // Total items across all pages
    "totalPages": 5,         // Total pages available
    "lastPage": false,       // True if no more pages exist
    "sortingType": "desc"    // 'asc' or 'desc'
  }
}
1.3 Standard Error Envelope (ErrorResponseDTO)
Used for 401, 403, 404, and standard 400 business rule exceptions.

json

{
  "message": "string",       // User-facing error message (e.g. "Policy not found")
  "success": false,
  "errorType": "NOT_FOUND",  // e.g., BAD_REQUEST, NOT_FOUND, UNAUTHORIZED
  "statusCode": 404,
  "timeStamp": "2023-10-27T10:00:00",
  "requestPath": "/api/policies/99"
}
1.4 Validation Error Envelope (ValidationErrorResponseDTO)
Used for 400 Bad Request when form input validation fails (e.g. @Valid failure).

json

{
  "message": "Validation failed",
  "success": false,
  "errorType": "BAD_REQUEST",
  "statusCode": 400,
  "timeStamp": "2023-10-27T10:00:00",
  "requestPath": "/api/auth/register",
  "fieldErrors": {           // Key-value map of form field names and their specific localized error message
    "email": "Enter valid email.",
    "password": "Password must be at least 8 characters."
  }
}
2. Request & Response DTO Schemas by Domain
2.1 Authentication & User Management
UserRequestDTO (Customer Registration)

fullName: string (Regex: ^[a-zA-Z\s]*$, Length: 2-100)
email: string (Valid Email)
password: string (Length: 6-15, Regex: ^(?=.*[A-Z])(?=.*[a-z])(?=.*\d)(?=.*[@#$%^&+=!]).{6,15}$)
mobileNumber: string (Regex: ^\+[1-9]\d{7,14}$)
CreateStaffRequestDTO (Staff Registration)

Inherits UserRequestDTO
productSpeciality: enum ProductType (e.g. HEALTH, AUTO, LIFE)
LoginResponseDTO

userId: long
fullName: string
email: string
role: string (e.g. ROLE_CUSTOMER, ROLE_ADMIN, ROLE_INTERNAL_STAFF)
token: string (JWT)
tokenType: string (Bearer)
UserResponseDTO

id: long
fullName: string
email: string
mobileNumber: string
role: string
isActive: boolean
emailVerified: boolean
phoneVerified: boolean
createdDate: datetime
updatedDate: datetime
productSpeciality: enum (Only present for STAFF)

id: long

processingFee: decimal
gstPercentage: decimal
isActive: boolean
remarks: string
createdDate: datetime

3. Swagger / OpenAPI Integration
The backend is configured with springdoc-openapi-ui. For real-time, interactive exploration of these contracts, frontend engineers can view the live Swagger documentation:

Swagger UI: http://localhost:8081/swagger-ui.html
OpenAPI JSON Spec: http://localhost:8081/v3/api-docs
Use the OpenAPI JSON to auto-generate frontend TypeScript clients via openapi-typescript-codegen or swagger-typescript-api if desired.
